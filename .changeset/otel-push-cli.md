---
'@wdio/opentelemetry': minor
---

New `wdio-otel` CLI pushes the tests listed in devtools artifacts manifests to an OpenTelemetry collector as spans (the WebdriverIO, Selenium and Nightwatch adapters write a manifest in `mode: 'telemetry'`, or in trace mode with `emitArtifactsManifest: true`; WebdriverIO also writes one unasked when an Allure reporter is configured, and Selenium when an allure-js-commons runtime is active, unless `emitArtifactsManifest: false` is set). Each test attempt is a root span carrying its status, duration and failure, with the trace and span ids the run recorded, so re-pushing a manifest that carries attempt records produces the same spans; with `--trace-zips`, the actions of a retained trace zip become child spans. Export runs in bounded sequential batches, and a failed batch stops the push with an exact report of spans that reached the collector, spans that did not, and the tests not sent. Root spans carry session, test uid and browser attributes, CI pipeline and ref attributes are detected on GitHub Actions and GitLab CI, and `test.suite.name` is the spec file as the adapter recorded it. `--run-id`, `--console-messages` (console text, off by default, may hold personal data) and `--ignore-parent-sampling` (manifests under an unsampled `TRACEPARENT` are skipped unless set) are new flags. See the package README.
