The dashboard builds the same Cucumber tree on WebdriverIO 9.x and 10.2. A plain scenario, and a scenario reported as a test with `scenarioLevelReporter`, no longer take part of their id from WebdriverIO's feature id, whose form 10.2 changed to the file's path from `rootDir`; on 9.x, two feature files with the same name in one worker both reach the dashboard. A failed Cucumber hook (`BeforeAll`/`AfterAll` of a feature, `Before`/`After` of a scenario) shows as a failed row of the feature or scenario it belongs to, in sequential and parallel (`parallelMode: 'contexts'`) runs alike, an `AfterAll` below the scenarios, and each failed hook is its own row (`After`, `After #2`). A retried test is one row: its next attempt replaces the failed one on the same id and carries the retry count, the same-titled tests of parallel contexts each keep their own, and the failed attempt is recorded against the test that was retried in the per-test attempt ledger that the retry-aware trace policies read. When a Cucumber scenario runs again after a retry, the dashboard drops the earlier attempt's rows, so a failed hook of that attempt no longer stays under a scenario that passed.
