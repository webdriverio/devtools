Typed passwords and credentials are now redacted by default: before an element's `send_keys` runs, the adapter reads the element's `type` property (capped at 2 s) and, for a password field, replaces the typed value with `••••` in that row and every frame sent after it, and so in the trace archive the backend builds from them. The values of `Authorization`, `Proxy-Authorization`, `Cookie` and `Set-Cookie` in every network row are replaced too, as are cookie values a navigation row records and the `value` of every cookie a command returns. All of it follows `mask_inputs` (`--devtools-no-mask-inputs`, `DEVTOOLS_MASK_INPUTS=0` turn it off). New `secrets` setting for any other value, redacted from the start of the run: `enable(secrets=["...", {"env": "LOGIN_PASSWORD"}])`, `--devtools-secret VALUE`, `--devtools-secret-env NAME`, the `devtools_secret_envs` ini key or `DEVTOOLS_SECRET_ENVS=NAME1,NAME2`. Matching covers JSON-escaped, URL-encoded and form-encoded forms. After one field-type read times out, that session reads no more. A value shorter than 4 characters, or an unset variable, is skipped, and one warning gives the count of skipped entries. A `--devtools-secret` value is dropped from the Run-all and rerun commands sent to the dashboard, so a dashboard rerun does not redact it; `--devtools-secret-env` is inherited by reruns. Screenshots are not redacted.
