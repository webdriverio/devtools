# script — design notes and known debt

Owns the collector bundle injected into the page under test (`packages/script/src`).

## Known debt

- **A trace stores the stylesheets and fonts its pages used, and the collector's reads of them are not network rows.** In trace mode (`traceResources`, default `'styles'`) the drain asks the page collector for them (`collectorDrainExpression(forceAnchor, mode, storedKeys)`; Python runs the backend's `collectorDrainResources` with the keys as its argument), and `script/src/collectors/pageResources.ts` reads each `link`/`css` load Resource Timing reported back through the fetch the page had before the network patch, from the HTTP cache, with a timeout, cross-origin only where CORS allows (a same-origin stylesheet falls back to its parsed rules). A drain names the `resourceUrlKey`s already stored (FNV-1a, mirrored in Python with a mirror-vector section) so a later document does not read or ship them again. The collector claims the Resource Timing entry that starts at its own read, so the page's rows never list it; a driver-side source still does, so each drain reports its reads (`ResourceReRead`) and the trace writer (`trace/src/trace-network.ts` `withoutResourceReReads`) drops, per read, the one row it can tell is that read: same URL, a browser-clock start (`NetworkRequest.wallTime`, set by every driver-side source) at the read's start and well after the page's own load, and no `Sec-Fetch-Dest` naming a stylesheet or font. A row without `wallTime` is kept, so a read the writer cannot identify stays as a second row rather than a real load being dropped. The filter lives in `trace` because the backend builds Python's zip with the same writer, and the backend keeps `pageResources`/`resourceReReads` for that writer without forwarding them to dashboard clients. A live drain names no mode, so live mode reads nothing back. Residual: the read's start is the page's `performance.timeOrigin + now()` and `wallTime` the browser's event clock, which agree on one machine but can drift apart after the host sleeps, and a page's own `fetch()` of a stylesheet URL at the moment of a read can be taken for it. The writer stores only what each archive's DOM stream references, resolved against each document's own `<base href>` exactly as the player resolves it (`shared/document-base.ts`): links, `<style>` text, style attributes, then `url()`/`@import` inside stored stylesheets, scanned by `shared/css-urls.ts`, a linear tokenizer that decodes CSS escapes. Each body is stored once by sha1 under `resources/`, indexed in `page-resources.ndjson`, capped per archive by `PAGE_RESOURCE_LIMITS`. Every adapter drains again, bounded, while reads are in flight before each per-test slice and at session end.
